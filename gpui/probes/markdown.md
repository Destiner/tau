# Markdown / code-block probe

Run from `gpui/`: `cargo run --bin markdown-probe` for an interactive native window, or `cargo run --bin markdown-probe -- --capture /tmp/markdown-light` (`--dark` for dark mode). `--list-checks` prints the probe metadata. Capture uses headless Metal, writing screenshots and `checks.json` without opening a persistent window.

## Controls

- **Reset** restores the heading, paragraph, inline code, safe link, list, table and Rust fence.
- **Mixed Code** shows Rust (including Unicode), JSON, an unsupported language and an empty fence. The code blocks use actual Syntect parsing; unknown languages remain uncolored.
- **Long Code** replaces the document with a long line. Opt-in Base code-block scrolling shapes the actual mono glyphs to determine intrinsic width, keeps hard newlines, and clips the code inside a horizontal wheel viewport; the copy action remains pinned to the visible block. Vertical wheel events still scroll the outer Markdown list.
- **Open Fence** shows incomplete Rust. **Append Chunk** calls `TextViewState::push_str` for three bounded chunks, closing the fence on the third. Outside stream mode, Append Chunk starts the stream and adds its first chunk; further clicks after completion do nothing.
- **Tall Page** loads 24 sections to exercise the vertical block list.
- **Copy Code** writes the actual `CodeBlock::code()` to the clipboard on click, with an acknowledgement. In capture mode GPUI's `TestPlatform` keeps the clipboard **in memory** (not the user's pasteboard); scripted checks read back the text. Clicking the rendered link only records its destination locally: no browser or network. Drag across the heading or the code to test Base pointer selection.

## Highlighting API

`gpui/src/probes/highlight.rs` exports `code_block_highlighter(dark: bool) -> CodeHighlighter` (a stable `Arc<dyn Fn(&CodeBlock) -> Vec<(Range<usize>, HighlightStyle)> + Send + Sync>`). Install it with `TextView::shared_code_block_highlighter(highlight::code_block_highlighter(dark))` in file viewer/activity views. The helper caches Syntect syntax sets and themes once and its `Arc` per appearance, letting Base cache each code block's highlights by identity. Syntect's line parser retains state across lines; ranges are UTF-8 byte offsets into `CodeBlock::code()`. Unrecognized or absent language and parser errors produce no spans. Appearance uses InspiredGitHub / base16-ocean.dark. The binary imports the helper directly; no other probes are affected.

## Verification

`cargo test --bin markdown-probe` tests Unicode UTF-8 byte boundaries, real multi-colored Rust parsing in both themes, unknown/empty languages and unfinished input. `cargo clippy --bin markdown-probe -- -D warnings` checks the owned binary. Headless `--capture` and `--dark --capture` each run 21 Metal checks, including real horizontal pixel-wheel events on the code line, a large swipe to the last glyph (`omega`) and its pointer selection clear of the copy action, a reverse swipe, pinned copy, pointer selection before/after movement, and clipboard readback. The scripted geometry requires the copy action to stay at x=730–840 and y=220–290 (logical pixels) while one-line code stays short. In light and dark captures, the pixel at physical (200, 490) changes from the code background to a visible blue selection fill after the scrolled drag; syntax-colored glyphs and clipped ends are visible in both screenshots. The prepared Base crate passes 1,250 upstream library tests (two new regressions: shaped width and geometry). Earlier captures passed 14 checks each, including clipboard readback, code selection, incremental parsing, scroll, link interception and rendered mixed-language fences. `mixed-code.png` in each capture visibly paints Rust and JSON in multiple syntax colors, while the unknown block is neutral. A pixel assertion over the JSON line (x=100–520, y=590–630 at 2×) found 1,272 chromatic pixels in light and 320 in dark; the unknown-language line (same x, y=700–745) had zero in both. Screenshot ink checks also guard against blank Metal frames. Captures do not write to the OS clipboard.

## Base opt-in and limitations

`TextViewStyle::with_code_block_horizontal_scroll(true)` enables the dependency patch; the default remains wrapped code. Base shapes each hard line in the same theme mono font, font size and highlighted runs as the rendered `Inline`, then sizes its horizontal track to the maximum measured line width (with a 1px safety margin). The existing `Inline` owns pointer selection and highlighted text; the existing `horizontal_scroll_area` / `ScrollableMask` routes horizontal wheel input and lets vertical wheel input reach the enclosing list. Opted-in actions are a stationary flex sibling of the viewport, reserving their actual layout width so no endpoint is concealed. The default wrapped layout retains its original absolute action overlay. The scroll handle uses the code block's source span, stable across many append-only updates; replacing the document may reset its offset. No separate code editor model is introduced. No file preview, external navigation, streaming timer, or editable Markdown source control is included; editing means replacing/appending source through controls.

# Command palette probe

Run `cargo run --bin palette-probe` from `gpui/`. Capture the isolated native window with `cargo run --bin palette-probe -- --capture /tmp/tau-palette-light` and `cargo run --bin palette-probe -- --dark --capture /tmp/tau-palette-dark`. Each directory contains Metal PNGs and `checks.json` with interaction assertions. `--list-checks` lists the sequence.

The Base `Dialog` contains a real Base `Input`, grouped searchable synthetic commands, disabled actions, shortcuts, nested recent sessions, and a bounded scrollable result list. ⌘K or the trigger opens it. Escape backs out of the nested page before dismissing the palette; the Back button also returns to the root. Native Tab traversal cycles through the search, Close, and (when nested) Back controls. The composer draft and focus survive dismissal. Command activation only increments local fixture counters; no filesystem, network, session or Pi operations occur.

The scripted checks observe focus handles, actual input contents and caret positions, fixture counts, selected-row and viewport geometry, scroll offset and surface bounds at intermediate points in both appearances. They exercise composer left/right/up/down/Home/End editing with the palette closed, search insertion and list navigation while open, then query, selection, and draft state across dismissal and reopening. The row bindings use GPUI's `PaletteSearch > Input` ancestor context, so Base Input editing outside the palette keeps its own bindings. This is a native interaction fixture, **not** production wiring, Vue visual parity, a persistent window, a screen-reader audit, or a real command catalogue.
